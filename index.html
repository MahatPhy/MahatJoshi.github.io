About

I'm working toward a career building guidance, navigation, and control software for spacecraft.

I read NASA's Apollo-era guidance and navigation papers and the X-15 aerodynamics reports because they're some of the clearest records available of solving hard problems under real constraints. I hold my own work to a similar standard: build the simplest version that is correct, verify it independently, then move to the next piece.

I don't rely on jargon. If I can't explain a system in plain language, I don't understand it well enough yet, and I would rather find that out early than after something ships. I work in steps large enough to matter and small enough that I don't lose track of what I'm building or why.

SpaceNet

2026 — present · Independent, for supervisor Khang Nguyen
Astrodynamics

C++ · Python (pybind11) · SOFA · CMake · GitHub Actions

A satellite sun-vector library with two independently coded reference-frame transformation chains, built specifically so they could argue with each other.

  • Implemented both the classical Vallado 4-frame method and the IAU-2006/2000A method via the SOFA C library, cross-validated to sub-0.01° accuracy against Vallado's own published test cases.
  • Diagnosed a ~29-day periodic discrepancy between the two chains by inspecting a plot with no leads, and traced it to an omitted lunar gravitational perturbation term — the disagreement peaks exactly at quarter-moon geometry.
  • Designed the architecture around a self-formulated "feudal programming" pattern: every module trusts its inputs and guarantees its outputs, with all defensive validation concentrated at explicit handshake boundaries.
  • Built a three-tier API — C++ core, pybind11 bindings, and a Python convenience layer with automatic Earth Orientation Parameter fetching — backed by 37 passing tests in CI.

Active Feedback Stabilization of a Continuous Z-Pinch

2026 · Independent research · target publication 2028
Research

Magnetohydrodynamics · Delay-differential control theory

Control theory applied to keeping a column of superheated plasma where you put it — under realistic sensor and actuator delay.

  • Derived a magnetohydrodynamic equilibrium model linking a boundary perturbation to a normalized magnetic-pressure perturbation via the Maxwell stress tensor.
  • Formulated a control-oriented instability model and derived a delayed-feedback amplitude equation from a Lyapunov-style energy proxy, capturing finite sensor/actuator latency.
  • Decomposed the resulting closed-loop characteristic equation into coupled real/imaginary stability conditions — the same class of delay-differential analysis used in real-time control-loop design.

Real-Time Market Simulator

ECE243 — Advanced Embedded Systems
Embedded

Bare-metal C · RISC-V (Nios V) · Intel DE1-SoC FPGA

Stochastic calculus, running on a chip with no operating system and no math library.

  • Derived a discrete-time geometric Brownian motion pricing engine from the continuous-time Itô SDE, and implemented sqrt, log, exp, sin, and cos from first principles for a target with no libm.
  • Designed an interrupt-driven, no-OS architecture: a hardware-timer ISR drives price ticks, a KEY-button ISR handles order entry, all synchronized through volatile shared state.
  • Found and fixed five quantified defects, including a Taylor-series early-exit bug that introduced systematic upward price drift, and a signed left-shift undefined-behavior bug in the exponential's range reduction.
  • Owned the full math/processing engine end-to-end while a partner owned the VGA rendering — praised in the course demo for explaining Itô-calculus concepts clearly to a non-specialist audience.

14 MHz Push-Pull RF Power Amplifier

ECE295 · Team Lead, RF Subsystem
Analog RF

MATLAB · Analog circuit design

While most of the class went digital, this team built a fully analog transmitter — deliberately, for the redundancy it buys.

  • Selected a push-pull Class AB/B architecture (2N3904/2N2222 pre-amp driving IRF510 MOSFETs) over a digital approach, trading complexity for flux cancellation and even-harmonic suppression.
  • Built a full MATLAB simulation suite — DC bias, small-signal AC and noise, transient (ODE45), and PCB-parasitic analysis — across the pre-amp, power amp, and cascaded chain.
  • Documented critical failure modes ahead of hardware bring-up: thermal runaway from the IRF510's negative Vgs(th) temperature coefficient, drain overvoltage from transformer leakage inductance, and VHF parasitic oscillation — each with a quantified mitigation.
  • Kept the team's simulation and verification documentation current through deadlines, and diagnosed real hardware failures (a broken power-switch IC, a damaged PCB trace) separately from the failure modes the simulation had already predicted.

FPGA Pong

ECE241 · with Ava Haji Hosseinali
Digital Logic

Verilog RTL · Intel DE1-SoC FPGA

Pong, built entirely out of clocked digital logic — no CPU, no software, just finite state machines.

  • Designed an 8-state FSM governing paddle draw/erase/move behavior, gated to a once-per-frame timing reference derived from a single D-flip-flop edge detector on VGA vertical sync.
  • Implemented a two-stage flip-flop synchronizer and counter-based debounce circuit to bring noisy mechanical pushbutton input cleanly into the clock domain.
  • Traced a rendering bug — erase-then-redraw sprites occasionally wiping the static background — to the lack of a frame buffer, and documented it plainly rather than hiding it: clearing the whole screen became the win condition.

AlphaMax

2025 · Independent research
Agentic Systems

Python · SEC EDGAR API · Agentic LLM tooling

Where "feudal programming" actually came from — a research vehicle for minimizing LLM context usage, not a trading product.

  • Built a local, never-deployed financial-analysis agent with a custom SEC EDGAR API client to study context-minimization strategies for agentic pipelines, around the CISCO/AGNTCY Open Agent Schema Framework release.
  • Formulated the "feudal programming" module pattern here first — modules trust validated inputs and guarantee validated outputs, with all paranoid checking concentrated at handshake layers — specifically so an LLM agent only needs a short docstring contract, not the module internals.
  • Reused and refined the same pattern, unprompted, as SpaceNet's core architecture a year later — evidence it's a durable habit, not a one-off idea.
